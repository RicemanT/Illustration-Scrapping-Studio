# Implementation Guide

## Product goal
Build a local FastAPI + React artist dataset curator. Each artist is one folder with its own provider query and completely independent image + ground-truth sidecar pairs. Preserve raw source metadata, deduplicate only inside the owning folder, support review, and export trainer-ready datasets in a dense dark gallery UI.

## Providers
Danbooru, Gelbooru, e621; DeviantArt and Pixiv via gallery-dl; ArtStation and Twitter/X via gallery-dl where the extractor works; Pawchive only with a stable permitted endpoint. Every provider must expose capabilities, auth state, pagination, rate limit, search, lookup, download, and normalized metadata. Unsupported sources must report unavailable clearly.

## Architecture
Backend: Python 3.11+, FastAPI, httpx, Pillow, imagehash, imageio-ffmpeg, SQLite. Frontend: React 18, Vite, Tailwind, TanStack Query. Storage defaults to `library/index.db`, `images/<folder-slug>/<sha256>.<ext>`, `thumbnails/<folder-slug>/<sha256>_thumb.jpg`, and `exports/<folder-slug>/`, but the entire library root is selected with `ARTIST_LIBRARY_PATH`. Add config.toml/.env, structured errors, provider registry, migrations, and a replaceable background job interface. The browser may target a local or remote backend; the backend that owns the library also performs downloads, decoding, hashing, and jobs.

Recommended modules: providers/base.py, booru.py, gallery_dl.py, registry.py; services/search.py, import_service.py, images.py, dedup.py, media.py, metadata.py, sync.py, jobs.py, tags.py, qa.py; routes/search.py, imports.py, exports.py, jobs.py, settings.py.

## Data model
`Folder` is the canonical product term. Retain the legacy SQL `collection`, `collection_source`, and `collection_image` names solely for non-destructive compatibility. `image.folder_id` is the canonical owner, image hashes are unique per folder, and a membership row must match that owner. The same bytes or remote post imported into two folders produces two image rows, two physical image files, two sidecars, and independent provenance. Never silently overwrite source metadata: create versions/snapshots.

Artist-folder queries are human-readable: a spaced value such as `namako daibakuhatsu` is stored and shown with spaces but translated to the provider's single canonical artist tag for both automatic Sync and Import/Preview. Users never need to type provider underscores. Explicit filters such as `rating:safe` remain separate query tokens.

## Phase 1 — Foundation
Config, idempotent migrations, startup scripts, health/provider status, folder/image/source/tag CRUD, static serving, structured API errors, demo fixtures. Acceptance: fresh install, existing DB migration, CRUD, build passes.

## Phase 2 — Multi-provider search, ingest, and core deduplication
Provider registry; three booru adapters; remote search with cursor pagination; import preview; selection-based import batches; cancellable folder sync and import jobs; safe temp download/cleanup; normalized metadata/tags; folder-scoped SHA256/MD5 exact dedup; pHash/dHash Hamming comparison; Czkawka-inspired 256-bit gradient hashing and cached fingerprints; XnView-style color/layout scoring; folder-local candidate scans; side-by-side review and confirmed metadata-preserving merge. Perceptual matches must never be deleted automatically. Cancellation interrupts active network work, cleans temporary downloads, retains atomically completed pairs, and does not advance the page cursor. Acceptance: search without download, import subset, cancel an accidental operation, idempotent same-folder reimport, independent cross-folder imports, raw metadata visible, and visual candidates safely reviewed.

Batch image deletion follows the folder-owned model: move the selected image, sidecar, and thumbnail out of the active folder into a durable `library/.trash/<token>` recovery snapshot; clear active folder ownership and review membership together; and restore the complete pair and metadata on Undo. Only the latest batch per folder is retained, matching the "Recover last deletion" UI and preventing hidden recovery copies from accumulating indefinitely.

## Phase 3 — Ground-truth tag curation and original-media frame extraction
Preserve provider tags as immutable provenance; store user add/remove overrides; edit the complete effective tag list per image; batch add, remove, or replace tags across gallery selections; immediately synchronize UTF-8 sidecars; normalize underscores to spaces; provide durable undo. Every effective sidecar follows one stable category order: canonical artist trigger, character tags, copyright/series tags, species tags, general tags (including counts such as `1girl`, `2boys`, and `3others`), then metadata tags when enabled. Preserve provider order and explicit replacement positions within each category. Batch replace changes only selected images containing the old effective tag, keeps non-matches untouched, and inserts the replacement at the old tag's exact effective position so trigger ordering is stable. Folder creation offers an optional artist template (default `Drawn by {artist}`). Its `{artist}` value is always the normalized lowercase folder name, never a provider profile/display name, so a folder named `herheim` produces `Drawn by herheim` for every imported asset. Only Danbooru, Gelbooru, and e621 may contribute automatic non-artist ground-truth tags. e621's dedicated species array populates the species section. Gelbooru's flat post tag string is categorized through its batched tag-index API before ingest. DeviantArt, Pixiv, Twitter/X, ArtStation, Pawchive, and any future unapproved source retain all tags as read-only provenance but contribute no automatic trainer tags. Provide global and per-folder inclusion toggles for the canonical artist trigger and the trusted booru character, copyright, species, general, and metadata sections; metadata is excluded from ground truth by default. For animations and video containers, extract one representative frame from the original media. ZIP/CBZ and RAR/CBR originals yield the naturally ordered middle still frame, or a frame decoded from a contained video when no stills exist. If original extraction fails, skip the post; never substitute a low-resolution provider thumbnail for training. Retain the original format, URL, archive member, and decoder provenance. Final trainer normalization is specified in Phase 4. No post-import upgrade workflow and no natural-language caption generation.

## Phase 4 — Dataset validation and optional export
Every newly imported still passes through one deterministic trainer pipeline before hashing and storage: decode and apply EXIF orientation, enforce a universal minimum of 512px on both axes plus any stricter per-folder limits and aspect-ratio limits against the actual decoded frame, downscale only when the longest side exceeds 2000px using OpenCV `INTER_AREA`, then encode once. JPEG input remains JPEG at quality 100 with 4:4:4 chroma; PNG and every other decoded input become lossless WebP with method 4. Never upscale. Animation, video, and archive frames follow the same rule. ZIP selection ranks repeated frame sequences by sequence size and pixel area so embedded thumbnails do not beat original frames. Record source/output dimensions, formats, algorithm, and settings in immutable source provenance.

Validate missing files/sidecars, collisions, corrupt images, formats outside JPEG/lossless-WebP, either axis below 512px, dimensions above 2000px, unsupported originals, and empty ground-truth tags. If a separate export folder is needed, copy or link each canonical image with its existing curated sidecar and a provenance manifest. Do not generate prose captions. Existing legacy library files are not silently rewritten; validation identifies them for removal or explicit re-import.

Implemented: the folder Dataset tab runs non-destructive validation of ownership, canonical paths, sidecars, decodability, SHA-256 integrity, supported still formats, legacy provider-preview imports, case-insensitive collisions, and effective curated tags. Errors gate exports; a historical low-resolution provider preview is an error and must be deleted/re-imported. Each export is a new `library/exports/<folder-slug>/<export-id>/` snapshot using copies or hardlinks with per-pair copy fallback. `manifest.json` contains folder identity, hashes, dimensions, review state, effective tags, derived-media origin, and complete versioned source metadata. Existing sidecars are transferred byte-for-byte and no captions are generated. Sync and selected-import jobs stream each original file to disk and expose a separate current-file bar with downloaded/total bytes, average MB/s, transfer ETA when `Content-Length` is available, and local processing/extraction state; the existing post-count bar remains the overall job indicator.

## Phase 5 — Jobs and incremental sync
Cursor persistence, background jobs, sync now/all, progress polling or SSE, retry/backoff, scheduled sync, history. Sync must resume and be idempotent; item failures must not abort a batch.

Completed: Sync and selected Import batches use a global, user-selectable worker count from 1-4 (default and recommended: 2). Workers overlap provider-admitted downloads and CPU-heavy decoding/normalization without blocking the async server. Provider request starts remain rate-limited, SQLite source-version allocation and sidecar replacement are concurrency-safe, and duplicate bytes discovered by two workers converge on one folder-owned image row. Progress exposes every active file independently while retaining the overall completed-post count. Cancellation stops queued work, drains active decoder threads safely, and keeps completed image/sidecar pairs.

The shared ingest hot path is optimized without changing training pixels or source policy. A provider asset already present in the same folder is recognized by `(provider, remote_id)` before its media is transferred or decoded; metadata/tag provenance is still refreshed idempotently. New files stream in 1 MiB chunks, SHA-256 and MD5 are calculated in one pass, and the finalized trainer image is decoded once for dimensions, fingerprints, and its thumbnail. Lossless temporary video/animation/archive frames use fast low-compression PNG because the temporary file is immediately decoded into the unchanged final JPEG-quality-100/lossless-WebP policy. Incremental duplicate checks prefilter impossible aspect-ratio matches in SQLite. Booru request starts retain their configured site-safe interval but do not add a redundant full delay when that interval has already elapsed.

Every folder sync and Sync All run is a durable SQLite job with parameters, bounded logs, progress, aggregate results, trigger, timestamps, cancellation state, and restart recovery. Manual Sync All opens an options dialog for amount per enabled folder/source, latest/oldest order, and optional From/To dates; these parameters are recorded with the job and applied consistently to every source. Sync All is a real cancellable background job; one provider/folder failure is recorded without aborting the remaining sources. The Dashboard shows durable history plus live per-worker bytes, MB/s, ETA, and processing state. Opening the folder currently handled by Sync All attaches to that same job and renders the normal detailed folder progress panel. The global header retains a compact Sync All indicator. A persistent interval scheduler (minimum 5 minutes) runs all enabled sources with a configurable per-source amount and can be triggered immediately from Settings. Scheduled runs always check new posts first and spend remaining capacity on older backfill.

Incremental state separates the newest successfully handled remote ID (`last_cursor`) from the older-catalog pagination position (`backfill_cursor`). Each normal latest sync first consumes new IDs oldest-first from the high-water mark, then uses remaining capacity to continue older backfill. Historical oldest/date-filtered requests do not mutate either automatic cursor. Neither cursor advances when an item errors or a page is canceled, so restart replay is safe and exact deduplication makes it idempotent. Legacy page cursors migrate into `backfill_cursor` without data loss. Transient network/timeout/HTTP 429 or 5xx failures use three bounded attempts with 1s then 2s exponential backoff; permanent and per-item failures remain isolated and visible in history.

For gallery-dl profile feeds, a short extracted page means the older feed is exhausted; do not save the requested end offset as a cursor. When a previously saved offset reaches the end, refill the current run from the full newest page so a requested amount of 20 does not silently become a six-item head check. If newly posted work shifts an offset and produces overlapping assets, continue fetching older pages until the requested number of distinct candidates is selected or the feed ends; repeated non-advancing pages fail visibly without committing a cursor. Batch-deleting every active image in a folder clears its source cursors so a fresh scrape starts at the newest item. Parallel workers may complete out of order, but source selection and cursor movement follow feed order.

The same end-of-feed rule applies to Pixiv, Twitter/X, Pawchive, ArtStation, Danbooru, e621, and Gelbooru . ArtStation counts raw assets for its cursor but scans past process assets to fill the requested number of cover-matched works; an unresolved project still fails visibly. Gelbooru uses a fixed API page size and an absolute-item cursor so varying requested amounts cannot shift page boundaries. The requested amount counts source posts/assets considered, not guaranteed accepted training images: quality filters, duplicates, source failures, and multi-frame media can change the image count.

Every imported motion source (video, animated GIF/WebP/APNG, or ZIP/RAR animation sequence) is downloaded once and sampled at three separated positions. ArtStation video includes the original-resolution frame closest to its portfolio cover, plus two other distinct positions. Each usable frame is a separate normalized image with a stable `:frame:1`–`:frame:3` source identity and original-media provenance. Clips with fewer than three decodable/distinct frames or frames failing the folder quality floor yield fewer images; duplicate frames are not fabricated. A 20-post sync can therefore add up to 60 images. Selected imports use the same policy.

## Phase 6 — Pixiv and additional sources
gallery-dl executable/auth detection, Pixiv artwork/user import, multi-image and ugoira policy, ArtStation/Twitter adapters where supported, Pawchive capability detection. Redact secrets and preserve original URLs/metadata.

Implemented: gallery-dl is a pinned runtime dependency and is detected/versioned through the provider registry. Pixiv uses a backend-local refresh token. Twitter/X preferably uses a browser-uploaded Netscape `cookies.txt`, validated for a signed-in X session and stored privately on the backend that performs syncs; direct local browser-profile extraction remains an optional fallback. ArtStation and Pawchive need no mandatory credential. Settings reports setup state without returning secrets. All four adapters normalize creator tags, dates, canonical post URLs, stable per-asset IDs, original download URLs, dimensions, ratings, and redacted raw metadata. Those normalized tags are provenance only: they never enter ground-truth sidecars, whose only automatic artist identity is the lowercase folder-name trigger. Pixiv, Twitter/X, and Pawchive multi-image posts create one importable item per original asset. Pawchive animated GIF previews do not suppress a paired original video: both remain eligible original-media assets, and the video is downloaded and decoded at its own resolution. Pixiv ugoira archives, provider videos, and Pawchive archives enter the same original-media extraction and training normalization pipeline as Phase 3/4, and never fall back to provider thumbnails.

ArtStation intentionally selects at most one original media asset per project. The provider matches the portfolio `cover_url` to the same asset's size-independent CDN path, then downloads gallery-dl's highest available original tier while excluding the project's sketches and process images. ArtStation-hosted videos use the cover only as an in-memory visual reference to select one original-resolution frame plus two separated frames. Marmoset viewers and external video embeds use the matched attached project still. If a multi-asset project cannot be matched unambiguously it is skipped; the low-resolution portfolio cover is never stored as training data. Native extraction scans past process assets until the requested number of finished works is selected or the raw feed ends; one selected video can still create three training images.

ArtStation may reset or Cloudflare-challenge its `www.artstation.com` detail API even for public profiles. On those failures, use one persistent browser-TLS session to read `https://{artist}.artstation.com/projects` and each artist-hosted project page. Parse the real project image/video assets, crop-match the portfolio cover against medium previews in memory, then download the selected real image through `8k`, `4k`, `large`, `medium`, and `small` asset-tier fallbacks. The cover is never a download fallback. An unreachable project, undecodable comparison asset, or low-confidence match fails the sync without advancing its cursor, so a later retry cannot silently replace an original with a thumbnail. This path remains one finished item per project and is intentionally secondary to gallery-dl's native detail extraction when that API is reachable.

ArtStation's fallback resolves independent projects concurrently using the global parallel-worker setting, but returns them in portfolio order. Discovery emits durable per-project match logs plus transient inspection updates, project counts, elapsed time, ETA, and worker count. A forbidden secondary asset is retried once and then excluded from comparison; the selected surviving asset must still pass the normal visual-confidence gate.

Each folder source can override the folder's general artist query with its provider-specific profile URL, user ID, slug, or handle. Changing an override resets only that source's incremental state. gallery-dl sources use an offset feed strategy that reserves capacity to check the newest entries and spends the remainder on durable older-catalog backfill. Search/preview, selected import, folder sync, Sync All, scheduled sync, parallel workers, cancellation, progress telemetry, minimum-resolution checks, folder-isolated storage, and provenance preservation are shared with booru providers. Fixture tests cover JSON message parsing, stable multi-asset identities, ArtStation cover-to-original selection, original-resolution cover-guided video frames, ugoira/original archive handling, date filters, secret redaction, URL preservation, and ordered-feed cursor behavior.

### 7A. One typed local filter contract

- Define a validated backend filter model shared by gallery listing, counts, tag exploration, QA selection, and reapply-preview. Support required tags (AND), excluded tags (NOT), provider, rating, width/height ranges, review status, and favorite. Use explicit fields/chips first; a free-text query parser is optional, not a reason to delay the usable controls.
- Make the tag basis explicit: **effective ground truth** or **imported source provenance**. Never mix the two silently. Multiple required tags must all match an image; any excluded tag excludes it. A provider filter matches if at least one source record matches. Provider/rating provenance filters must use the latest version for each source, not stale historical snapshots. Specify and test how unrated images are included; do not infer a rating from pixels.
- Local dimensions refer to stored normalized images. Remote preview dimensions are provider hints until the original is decoded; clearly distinguish these from original-media quality checks. Keep names human-readable with spaces, preserving the existing normalization rules.
- Filtering is read-only: it hides results, never deletes images, changes sidecars, advances source cursors, or changes future sync settings. Future-ingest filters remain a separate, explicitly saved folder setting. Unsupported remote filters must be shown as unavailable or clearly marked as local post-filtering, never silently ignored.
- Perform pagination/filtering/counts in SQLite with bound parameters and appropriate indexes. Use deterministic ordering with an image-ID tie-breaker, bounded page sizes, and correct distinct-image totals even when many sources or metadata versions match. Do not load 100k images or their metadata JSON into browser memory. If effective tags need a materialized index, migrate/backfill it and update it transactionally on tag edits, policy changes, folder renames, imports, merges, and undo; sidecars remain derived output, not a second source of truth.

### 7B. Tag explorer and remote-preview integration

- In the Tags view, expose category, provider, search, and tag-basis controls. Counts mean distinct active images in the selected folder/filter scope, never tag rows or metadata versions. Show character/copyright/species/general/meta categories separately and the canonical artist trigger clearly.
- Clicking a tag adds a required filter; an explicit exclude action adds a NOT filter. Show active filter chips, result count, clear/reset, and a way back to the unfiltered gallery. Preserve selections by image ID across pages and never apply a bulk action to hidden/unselected images accidentally.
- Reuse Import preview for remote exploration, pagination, already-have state, date/order controls, and selected import. A preview is metadata/thumbnail discovery, not an original-media download. Requests remain provider-rate-limited and cancelable; provider limitations and partial/filter-empty pages are visible. Do not regress the corrected source-count/cursor behavior from Phases 5-6.

### 7C. Actionable, non-destructive QA

- Extend the existing Dataset validator with missing/broken thumbnails, missing provenance, and unresolved duplicate candidates, alongside its existing corrupt-file, hash, sidecar, dimensions, format, ownership, and path checks. Empty source tags are normal for untrusted tagging providers; only report missing ground truth when the folder policy actually expects it. Respect user-disabled artist/tag categories.
- For each issue return image ID, stable issue code, severity, relevant backend path, explanation, and allowed repair actions. Link issues to image detail and let the user filter the gallery to affected IDs. Duplicate candidates are review suggestions, not permission to delete or merge.
- Long scans/repairs run in a bounded, cancelable job with progress, errors, and resumable/restart-safe status using the established job infrastructure. Chunk database reads, avoid a long write transaction while hashing/decoding, and skip gracefully if an image is deleted during a scan. Keep the UI responsive on the user's 2-core laptop.
- Repairs require an explicit selection and confirmation. Initially allow regenerating a missing thumbnail from the stored image and rewriting a missing/stale sidecar from effective tags. Never overwrite manually curated tags with provider tags, silently re-download originals, upscale low-resolution files, or auto-delete corrupt/duplicate items. Record before/after results and cleanup temporary files on failure/cancellation. Thumbnail repair must not change image bytes, hashes, source metadata, or ground truth.

### 7D. Reapply filters safely

- Provide a dry-run preview against existing folder images: matched/unmatched counts, paginated affected IDs, reasons, and the exact filter definition. Reapplying does not re-scrape or re-encode the dataset.
- Default action is view-only. A separate confirmed action may mark the previewed IDs rejected/archived using the existing review system. If removal is offered, it must explicitly invoke the existing recoverable batch-delete flow and warn that a new deletion replaces the previous recovery batch. Preserve independent ownership across folders. Revalidate preview IDs before applying; do not silently widen the selection when new images arrive.

## Phase 8 — Reference UI and bulk workflows

### 8A delivered: groups and artist lists

- `artist_group` stores a name, stable safe directory slug and batch provider. `collection.group_id` is nullable; existing folders remain Ungrouped. The migration preserves folder IDs, all existing columns and relationships, replacing global folder-name uniqueness with uniqueness within a group. The same artist may exist independently in Danbooru and e621 groups.
- A grouped folder's existing `slug` field is now a relative namespace such as `danbooru-group-<suffix>/artist-name`. Images, sidecars and thumbnails use that prefix, so existing ingest/QA/export path resolution remains folder-owned. Group creation creates the image/thumbnail parent directories; bulk artist creation also creates empty artist directories. Group slugs include a collision-resistant suffix and are shown in the group page.
- `services/groups.py` and `routes/groups.py` implement group creation/listing, bounded UTF-8 list preview/import (5,000 lines / 1 MiB), explicit source enablement, and physical moves between groups or back to Ungrouped. BOM, CRLF, blank lines, underscores/spaces and repeated artist identities are handled; repeat imports skip existing identities within that group. Import creation is transactional; invalid lists create nothing. Importing a list does not start scraping.
- Moves retain folder/image IDs, tags, source cursors, review state and image bytes. A durable `folder_move` journal is committed before renaming directories; startup finishes interrupted moves **before** filesystem reconciliation and job recovery. Mutation requests are blocked if an interrupted move needs retry. Move paths reject traversal, symlinks and junctions. Pending sync/import/QA work must finish or be canceled before a move; pair-write locking also serializes exports and reconciliation. Historical immutable exports retain their original paths. Trash manifests retain their original storage paths; recovery restores into the folder's current namespace and updates restored image paths.
- Reconciliation understands group parents and artist children and never creates a parent group as an artist. Group deletion/renaming and nested groups are not part of this slice; existing artists can move freely when jobs are idle. Do not implement group deletion as a recursive filesystem purge.
- `POST /api/sync/group/{id}` reuses durable `kind=all` jobs with `parameters.group_id`, `group_name`, `provider` and a persisted artist/source snapshot. Only the group's provider is included, and membership/source enablement is rechecked before each artist. Restart cannot add later-created artists or widen the group. Batch progress, per-artist failures, cancellation and resumed jobs use the existing sync engine. One sync batch runs at a time. The global Sync All/schedule still means all enabled folders/sources.
- `Groups.jsx` provides create group → upload/paste list → preview → create folders → scrape group with amount/order/date options, progress and Stop. It also moves existing folders and explicitly enables a missing group provider without changing other sources. Group history is filtered server-side so unrelated later jobs cannot hide the last group batch. Sidebar sections are collapsible; New Folder also supports a group. All counts continue to use authoritative shared folder queries. Folder listing now batches count/source queries for large artist lists.
